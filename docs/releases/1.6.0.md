# Judais-Lobi 1.6.0

This release builds on 1.5.1 with more reliable multi-turn missions and clearer
evidence about what a model call used, retained and completed. It preserves the
version-1 mission event contract and the Python 3.10 minimum.

## What's changed

- **Load capabilities for the task.** Deferred skill selection activates tools
  from the caller's configured skill set and remembers selected skills across
  turns. Capability routing can select a relevant skill before declaring a tool
  missing. Unambiguous active tool namespaces resolve consistently; ambiguous
  names still require disambiguation. This does not broaden tool authorization.
- **Keep the current request in focus.** Typed task state separates the latest
  literal user request from model-interpreted intent. Source-bound selections,
  ordered answer mappings and staged drafts survive supported handoffs and
  resumes. Replace and append are distinct selection operations. Requested
  counts are not treated as completed work merely because the model says so.
- **Retain evidence across turns.** Private durable tool receipts preserve source
  identity and result references for later reads and grounding. Restart recovery
  restores the original conversation history. Missing or altered evidence is
  reported as unavailable, not reconstructed as fact; restoring a receipt does
  not dispatch the original tool again.
- **Handle long conversations and imperfect replies.** Window-aware compaction
  keeps source-linked recall and current-task references. Bounded output recovery
  and text continuation retain useful truncated answers rather than dropping
  them. These are recovery mechanisms, not a guarantee that every model reply
  can be repaired or that all historical content remains in the active window.
- **Explain usage and stopping.** Additive request metadata identifies calls,
  phases, observed parent relationships, available stop causes, estimated input
  budgets and compaction evidence. Cumulative token usage is distinct from the
  size of any single request. Reported, derived, estimated and unavailable
  values remain distinguishable. Cache and reasoning components retain their
  provider-specific relationships; they must not be added twice to totals.
  Nested tool-provider calls and internal retry usage are not claimed to be
  fully observed.
- **Protect diagnostics.** Credential redaction now covers credential-bearing
  query values and standalone JWT-shaped values in addition to existing secret
  handling.
- **Exercise the integration seams.** CLI/library equivalence, durable-state
  recovery, historical replay, deferred tool selection and subject-linked
  evidence gained regression coverage. Recorded benchmark evidence is scoped to
  its own fixtures; it is not a general model-quality or throughput guarantee.

## Integrator notes

Existing event consumers should continue ignoring unknown additive fields.
Telemetry does not change tool permissions, and a persisted task reference is
not an authentication credential. CLI task tracking is enabled by default;
library consumers opt in through the typed task context. Hosted consumers must
bind task scope to their own authenticated owner and conversation and retain a
stable private run store across application releases.

Consult [current task state](../current-task-state.md) and
[request metadata](../request-metadata.md) for the exact contracts. Test deferred
skill activation, a follow-up that changes the task, restart/resume, bounded
result recall and long-answer recovery against your own configured tools.
For telemetry, test absent values and partial coverage as well as successful
calls; a large cumulative total does not prove context overflow or compaction.

## Release verification

The release gates include `tests/test_packaging.py`, `tests/test_contract.py`,
`tests/test_docs_track_the_code.py` and `tests/test_platforms_doc.py`, plus the
affected runtime and consumer integration suites. The immutable release tag,
package metadata, source distribution and wheel must identify the same release.
Publication is complete only after both artifacts are available and the exact
published version passes installation and integration checks. See the
[maintainer release procedure](../../PLATFORMS.md#cutting-a-release-for-this-repositorys-own-maintainer).
